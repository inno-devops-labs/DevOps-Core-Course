# Lab 16 — Kubernetes Monitoring & Init Containers

## Overview

This lab focused on implementing Kubernetes cluster monitoring using the Kube-Prometheus stack and learning init container patterns.

The monitoring stack provides:

- cluster metrics collection
- visualization dashboards
- alerting
- node monitoring
- Kubernetes object monitoring

Init containers were used to perform setup operations before the main application container started.

# Task 1 — Kube-Prometheus Stack

## Stack Components

### Prometheus Operator

The Prometheus Operator automates deployment and management of Prometheus components inside Kubernetes.

It manages:
- Prometheus instances
- Alertmanager instances
- ServiceMonitors
- PrometheusRules

### Prometheus

Prometheus is responsible for collecting and storing metrics from Kubernetes components and applications.

It periodically scrapes metrics endpoints and stores time-series data.

### Alertmanager

Alertmanager handles alerts generated by Prometheus.

It supports:
- alert grouping
- deduplication
- routing
- silencing

### Grafana

Grafana provides dashboards and visualization for Prometheus metrics.

It allows monitoring:
- cluster health
- CPU usage
- memory usage
- network traffic
- pod statistics

### kube-state-metrics

kube-state-metrics exposes Kubernetes object metrics.

Examples:
- pod status
- deployment replicas
- StatefulSet information
- node conditions

### node-exporter

node-exporter collects hardware and operating system metrics from Kubernetes nodes.

Examples:
- CPU usage
- RAM usage
- disk usage
- filesystem statistics

# Task 3 — Init Containers

## Basic Init Container

An init container was implemented to download a file before the main application started.

## Init Container Configuration

```yaml
initContainers:
  - name: download-config

    image: busybox

    command:
      - sh
      - -c
      - |
        wget -O /shared/index.html https://example.com

    volumeMounts:
      - name: shared-data
        mountPath: /shared
```

## Shared Volume

```yaml
volumes:
  - name: shared-data
    emptyDir: {}
```

## Main Container Access

The main container successfully accessed the downloaded file.

Verification:

```bash
kubectl exec -it python-app-lab-0 -- cat /shared/index.html
```

Output:

```text

```

# Wait-for-Service Pattern

An init container was used to wait until a dependency became available.

## Wait-for-Service Configuration

```yaml
initContainers:
  - name: wait-for-service

    image: busybox

    command:
      - sh
      - -c
      - |
        until nslookup kubernetes.default.svc.cluster.local; do
          echo waiting for service;
          sleep 2;
        done
```

## Verification

The application pod remained in:

```text
Init:1/2
```

until the service became available.

After service startup:

```text
Running
```
