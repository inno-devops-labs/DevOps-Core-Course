# Lab 16 — Kubernetes Monitoring & Init Containers

## Overview

This lab implemented Kubernetes monitoring using the kube-prometheus-stack and demonstrated init container patterns.

The monitoring stack includes Prometheus, Grafana, Alertmanager, kube-state-metrics, node-exporter, and the Prometheus Operator.

## Task 1 — Kube-Prometheus Stack

### Components

| Component | Role |
|---|---|
| Prometheus Operator | Manages Prometheus, Alertmanager, and related custom resources |
| Prometheus | Collects and stores metrics from Kubernetes and applications |
| Alertmanager | Handles alerts generated by Prometheus |
| Grafana | Provides dashboards and visualizes metrics |
| kube-state-metrics | Exposes Kubernetes object state metrics |
| node-exporter | Exposes node-level CPU, memory, disk, and network metrics |

### Installation

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

helm install monitoring prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --create-namespace
```

## Task 3 — Init Containers
### Init Container Implementation

An `init-demo` pod was created in `k8s/init-demo.yaml`.

The pod contains two init containers:
1. `init-download`
- prepares a shared volume
- creates an `index.html` file

2. `wait-for-service`
- waits until Kubernetes DNS is available
- checks `kubernetes.default.svc.cluster.local`

The main container starts only after both init containers complete successfully.

### Apply Manifest
```bash
kubectl apply -f k8s/init-demo.yaml
```

Output:
```
pod/init-demo created
```
