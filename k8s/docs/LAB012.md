## 4. Task 4 — ConfigMap vs Secret

### Use ConfigMap when

- Data is non-sensitive configuration
- You need readable config files or env vars

### Use Secret when

- Data is sensitive (passwords, tokens, API keys)
- Access must be restricted and audited

### Key differences

- ConfigMap: plain configuration
- Secret: sensitive values, base64-encoded in manifest (and should be protected with RBAC + etcd encryption in production)

## 5. Bonus — ConfigMap hot reload

### 5.1 Default update behavior

Observed behavior:

- Updating ConfigMap does not instantly update mounted file.
- Typical delay: kubelet sync/cache period (can be around 1-2+ minutes).

![bonus-delay](screenshots/lab12/bonus-delay.png)

### 5.2 `subPath` limitation

- `subPath` mount is a file copy bind and does not receive live ConfigMap updates.
- For auto-update behavior, mount the full directory (used in this lab).

### 5.3 Implemented reload approach

Implemented Helm checksum annotation restart pattern in deployment:

- `checksum/config-file`
- `checksum/config-env`

When ConfigMap template content changes, pod template hash changes and Deployment performs rollout.

### 5.4 Verification

- Update ConfigMap-related values/file
- Run `helm upgrade`
- Confirm new ReplicaSet/pod created
- Confirm new config is present in pod

![bonus-checksum-rollout](screenshots/lab12/bonus-checksum-rollout.png)
