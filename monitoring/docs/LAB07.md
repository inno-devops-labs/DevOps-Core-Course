# Lab 7 — Observability & Logging with Loki Stack

## Overview

In this lab, I deployed a centralized logging stack using **Grafana Loki**, **Promtail**, and **Grafana**.  
The stack collects logs from Docker containers and visualizes them in Grafana.

The logging stack allows monitoring of application behavior, debugging errors, and analyzing request patterns.

Technologies used:

- Loki 3.0.0
- Promtail 3.0.0
- Grafana 12.3.1
- Docker Compose
- FastAPI application from previous labs

---

# Architecture

The logging architecture consists of three main components:

Application containers generate logs → Promtail collects logs → Loki stores logs → Grafana visualizes logs.


Application Containers
↓
Promtail (log collector)
↓
Loki (log storage)
↓
Grafana (visualization)


Promtail discovers containers using the Docker socket and sends logs to Loki.  
Grafana queries Loki using the **LogQL query language**.

# Configuration

## Loki

Loki was configured with:

- TSDB storage
- filesystem backend
- retention period: **7 days**

Example configuration snippet:

```yaml
limits_config:
  retention_period: 168h
```
TSDB storage was chosen because it provides faster queries and better compression.

## Promtail

Promtail collects logs from Docker containers using Docker service discovery.

docker_sd_configs:
  - host: unix:///var/run/docker.sock

Relabeling extracts container metadata and assigns labels:

* container

* app

* job

Example:

```yaml
relabel_configs:
  - source_labels: ['__meta_docker_container_name']
    target_label: 'container'
```
## Application Logging

The FastAPI application was updated to produce structured JSON logs.

Example log:

{
 "asctime": "2026-03-12 09:32:10",
 "levelname": "INFO",
 "message": "HTTP request processed",
 "method": "GET",
 "path": "/health",
 "client_ip": "172.18.0.1",
 "status_code": 200
}

Structured logging makes it easier to filter logs in Loki using LogQL.

## LogQL Queries

Example queries used in Grafana:

All application logs
{app="devops-python"}
JSON parsing
{app="devops-python"} | json | __error__=""
Health endpoint requests
{app="devops-python"} | json | path="/health"
Request rate
rate({app="devops-python"}[1m])
## Grafana Dashboard

A dashboard was created to visualize application logs.

The dashboard contains four panels:

1. Application Logs

Displays all logs generated by the application.

Query:

{app="devops-python"}
2. Request Rate

Shows the number of requests per second.

Query:

rate({app="devops-python"}[1m])
3. Health Requests

Tracks the number of health checks.

Query:

count_over_time({app="devops-python"} | json | path="/health" [5m])
4. HTTP Status Codes

Shows distribution of HTTP response codes.

Query:

sum by (status_code)(
count_over_time({app="devops-python"} | json [5m])
)

## Challenges

Several issues occurred during the setup:

Loki configuration errors

Initial Loki configuration failed due to missing compactor settings.

Solution: configure retention and compactor properly.

JSONParserErr in Grafana

Some logs could not be parsed as JSON because uvicorn outputs plain text logs.

Solution:

| json | __error__=""

This filters out non-JSON logs.
